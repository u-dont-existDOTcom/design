# Authority and Conflict Resolution

Design frameworks are subordinate to product truth and user intent.

## Authority order

1. Explicit user instruction and supplied truth.
2. Durable project context.
3. Correctness, accessibility, safety, ethics, and law.
4. Lower perceptual requirements.
5. Implementation boundaries.
6. Project identity.
7. Verified searched guidance.
8. Anti-pattern heuristics.
9. Agent taste.

## Conflict matrix

| Conflict | Resolution |
|---|---|
| Clear brief vs. anti-pattern warning | Preserve the brief; document the intentional deviation. |
| Established identity vs. catalog recommendation | Identity wins; use the catalog to improve execution. |
| Clarity vs. novelty | Fix the failing lower layer first. |
| Cross-project variety vs. within-project consistency | Vary unrelated products; preserve family resemblance inside one product. |
| Owner copy vs. layout convenience | Copy wins; change the layout. |
| Polish vs. factual integrity | Factual integrity wins absolutely. |
| Expert density vs. generic simplicity advice | Preserve required density; improve grouping and retrieval. |
| Clear winner vs. approval ritual | Select and continue. |
| Close valid candidates | Expose the trade-off and ask. |
| Destructive improvement vs. uncertain authorization | Preserve files and ask before deletion. |

## Intentional deviations

A deviation is intentional when coherent, repeated, tied to a documented purpose, and verified against truth, lower layers, and accessibility. Record the heuristic, purpose, evidence, risks, and verification.
